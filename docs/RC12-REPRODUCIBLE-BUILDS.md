# RC12 — Dependency & Build Reproducibility

## Objective

RC12 establishes the release-engineering gate for deterministic dependency resolution and repeatable builds. It does not fabricate lockfiles when the package registries are unavailable.

## Required stable-release evidence

1. `package-lock.json` generated by the pinned Node/npm toolchain.
2. `src-tauri/Cargo.lock` generated by Cargo.
3. Clean `npm ci` from an empty dependency directory.
4. TypeScript typecheck.
5. Full Vitest suite.
6. Production Vite build.
7. Cargo/Tauri check and release build.
8. SBOM and dependency provenance.
9. Build artifact hashes recorded with the release.

## RC12 reproducibility gate

Run:

```text
npm run verify:reproducibility
```

The gate records manifest SHA-256 values and explicitly reports missing lockfiles as `BLOCKED`. A `BLOCKED` result is not converted into a pass.

## Environment limitation observed for this RC

The qualification environment has Node.js/npm but no Cargo/Rust toolchain. The npm registry was also unavailable during lockfile generation, and the required package metadata was not present in the local npm cache. Therefore valid lockfiles could not be generated without inventing dependency metadata.

## Stable-release rule

RC status may carry reproducibility blockers. A stable `1.0.0` release must not: it requires committed lockfiles and successful clean-install/build evidence.
