# RC17.6 — Reproducible Build Harness

## Objective

RC17.6 converts dependency reproducibility from documentation into a hard release gate. The project must not certify a production release when dependency lockfiles or the native build toolchain are unavailable.

## Mandatory evidence

1. `package-lock.json` committed and validated.
2. `src-tauri/Cargo.lock` committed and validated.
3. `npm ci --ignore-scripts` succeeds from a clean checkout.
4. `npm run typecheck`, unit tests, and production build succeed.
5. Cargo/Tauri compilation and native tests succeed.
6. The exact source commit, lockfiles, toolchain versions, and build artifact digests are recorded.

## Fail-closed behavior

`scripts/verify-lockfiles.mjs` returns exit code 2 when required evidence is missing. It does not create or synthesize lockfiles.

## Current status

This artifact was produced in an environment without Cargo/Rust and without network access to resolve npm dependencies. Therefore no lockfile or dependency-backed build result is fabricated. The gate remains `BLOCKED` until executed in the controlled CI/build environment.

## Recommended execution

Run on a clean checkout in CI with network access to the approved registries:

```text
npm ci --ignore-scripts --no-audit --no-fund
npm run verify:lockfiles
npm run typecheck
npm run test
npm run build
cargo test --manifest-path src-tauri/Cargo.toml
npm run tauri:build
```

The resulting evidence must be attached to the release certification record.
